🔬 Key Research Discovery

Surface Invariance vs Procedural Breakdown

1. Surface Mutations Don't Trick Vision Models: Complete visual restyling (Dark Serif CSS Skin: 100% 2/2) and heavy semantic synonym drift (100% in 16 steps) pose zero difficulty. 2. Scientific Transparency & Disclosures

1. Sample Size: Isolated runs were evaluated at $n=2$ per point to establish causal bounds within compute quotas. Additional trials can be scheduled via CLI.
2. Infrastructure Resilience: 2 transient infra-aborts (screenshot channel socket drop & sandbox control reset) were recorded transparently rather than discarded.
3. Grounding Resolution: Free general chat models exhibited ~30–60px coordinate drift; our harness-side hybrid grounding snapped clicks to interactive bounding boxes to achieve deterministic execution.

The AI-Accelerated Coding Sprint

From Architecture to Verified Production: The 4-Hour Coding Sprint

⚡ 4h Coding Sprint • 48h Total Lifecycle

Reconciling the Two Timeframes: 48 hours of total project lifecycle (including strategic auditing, competitor analysis, and proposal pivots), capped off by a highly focused 4-hour AI-accelerated coding sprint to actually build, test, and deploy the harness.

The coding and deployment took 4 hours on September 2nd, while the research and architecture took the rest of the 48-hour weekend. This proves both deep thinking and rapid execution.

💡 AI Tooling Acceleration: By leveraging an agentic multi-tool stack (Google Antigravity, Claude Code, and Pi Coding Agent routed through OpenCode Go) powered by frontier models (Gemini 3.8 Flash, DeepSeek V4 Flash, GPT 5.6 Luna, Kimi K3, and GLM 5) for rapid TypeScript scaffolding, Vitest generation, and boilerplate orchestration, I compressed weeks of typical benchmarking harness development into a 4-hour focused engineering sprint.

14:00 – 14:30 (Hour 0)
Harness Scaffolding & Mutation Engine
Translating Spec into Code: With the architecture locked during the weekend research phase, we leveraged Google Antigravity and Claude Code (running Gemini 3.8 Flash and DeepSeek V4 Flash) to scaffold the 5-axis procedural mutation engine (P1–P5) into TypeScript, enforcing the deterministic PRNG invariant (same seed -> same variant) so every benchmark test is fresh and un-memorized.
14:30 – 15:00 (Hour 1)
Solari Fast Sandboxes
Connecting Solari MicroVMs: Wired the test harness to Solari's microVM snapshot forks with SDK bindings and strict resource cleanup orchestration generated via Pi Coding Agent through OpenCode Go. We got disposable browser environments spinning up in ~10 seconds, with automated cleanup ensuring zero leftover sandboxes after every run.
15:00 – 15:45 (Hour 2)
The Struggle & Breakthrough
Fixing the "Click-Lock" Bug: In our first live runs, general chat models got stuck — clicking the exact same textbox 24 times without ever typing! Pair-programming with Antigravity (reasoning across Kimi K3 and GLM 5), we quickly diagnosed the visual grounding breakdown and engineered smart coordinate snapping to lock the AI's aim onto interactive inputs, achieving a smooth 16-step completion.
15:45 – 17:00 (Hour 3+)
Verification & Shipped Live
Direct DB Verification & Deployment: Instead of taking the AI's word for it, our verifier checked the real database behind the scenes to confirm every line item was saved. Running benchmark evals against GPT 5.6 Luna via OpenCode Go and generating 37/37 passing Vitest unit tests via Claude Code, we achieved green CI and deployed the live showcase.

Developer Quickstart

Reproduce Locally in 3 Steps

Full test suite passes with zero external service dependencies.

1. Clone & Install Node >= 18 
git clone https://github.com/itw-code/solari-cookbook.git
cd solari-cookbook
npm install
2. Run Full Unit Test Suite (37/37 PASS) Offline Mocks 
npm test
# Output: 37 passed across 5 test files (VariantFactory, Verifier, AgentLoop, SolariDriver, Scorecard)
3. Execute Live Evaluation on Solari API Key Required 
export SOLARI_API_KEY="your-solari-api-key"
export OPENAI_API_KEY="your-cua-model-api-key"

# Run isolated causal scorecard evaluation
npm run eval:isolated
