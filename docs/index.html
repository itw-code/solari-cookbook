System Architecture

How ColdStart Evaluates Agents Cold

From seeded microVM snapshot forks to fail-closed SQLite verification.

01

Snapshot-as-Factory

Pre-bakes dependencies into a base microVM snapshot. At evaluation time, it boots new seeded variant environments in ~10 seconds via fast-forks, ensuring clean sandbox isolation without container pollution.

VariantFactory.ts • Seeded PRNG
02

Vision-First CUA Loop

The agent operates purely on viewport screenshots (1280x800) with zero DOM introspection or selector access. Harness-side hybrid grounding snaps coordinate predictions to active element boundaries.

AgentLoop.ts • Hybrid Grounding
03

Fail-Closed Verification

Completely ignores agent self-reporting. Recomputes expected mathematical totals from ground-truth task seeds and executes direct SQLite queries inside the microVM to verify SHA256 integrity checks (C1–C7).

Verifier.ts • Direct DB Channel

🔬 Key Research Discovery

Surface Invariance vs Procedural Breakdown

1. Surface Mutations Don't Trick Vision Models: Complete visual restyling (Dark Serif CSS Skin: 100% 2/2) and heavy semantic synonym drift (100% in 16 steps) pose zero difficulty. 2. Procedural Shifts Cause Total Failure: Converting a flat form into a two-step wizard flow (P2: 0.00% 0/2) causes the agent to step-cap at 40 steps without submitting.

Scientific Transparency & Disclosures

1. Sample Size: Isolated runs were evaluated at $n=2$ per point to establish causal bounds within compute quotas. Additional trials can be scheduled via CLI.
2. Infrastructure Resilience: 2 transient infra-aborts (screenshot channel socket drop & sandbox control reset) were recorded transparently rather than discarded.
3. Grounding Resolution: Free general chat models exhibited ~30–60px coordinate drift; our harness-side hybrid grounding snapped clicks to interactive bounding boxes to achieve deterministic execution.

The 4-Hour Build Story

From Idea to Verified Production in Under 4 Hours

⚡ Shipped Same-Day
14:00 – 14:30 (Hour 0)
The Idea & Architecture
Designing the Mutation Engine: We wanted to see if AI agents could survive unexpected UI changes. We built an engine that automatically mutates 5 key parts of a web app (field names, multi-step wizards, layout order, themes) so every test is fresh and un-memorized.
14:30 – 15:00 (Hour 1)
Solari Fast Sandboxes
Connecting Solari MicroVMs: Wired the test harness to Solari's microVM snapshot forks. We got disposable browser environments spinning up in ~10 seconds, with automated cleanup ensuring zero leftover sandboxes after every run.
15:00 – 15:45 (Hour 2)
The Struggle & Breakthrough
Fixing the "Click-Lock" Bug: In our first live runs, general chat models got stuck — clicking the exact same textbox 24 times without ever typing! We solved this by adding smart coordinate snapping to lock the AI's aim onto interactive inputs, achieving a smooth 16-step completion.
15:45 – 17:00 (Hour 3+)
Verification & Shipped Live
Direct DB Verification & Deployment: Instead of taking the AI's word for it, our verifier checked the real database behind the scenes to confirm every line item was saved. We packaged the benchmark results, set up 100% passing CI, and deployed the live showcase.
